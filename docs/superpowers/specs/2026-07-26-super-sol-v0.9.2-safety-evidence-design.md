# Super SOL v0.9.2 Safety and Evidence Design

Date: 2026-07-26
Target: `v0.9.2-rc1`
Baseline: `origin/main` at `d34bf0e`

## Decision

Super SOL v0.9.2 is a lightweight safety and evidence layer for stock Codex. It does not claim to
raise model capability, and its default path does not inject quality instructions. It preserves
stock Codex behavior unless a deterministic safety policy blocks an observed failure pattern.

The release candidate is evaluated for noninterference, incident prevention, audit completeness,
and bounded overhead. Quality uplift is not a promotion requirement and must not be advertised.

## Alternatives Considered

### 1. Safety and evidence by default (selected)

Keep deterministic loop, budget, secret, and benchmark-integrity enforcement. Make semantic
quality routing an explicit experiment. This matches the observed evidence: v0.9 felt lighter,
v0.9.1 did not earn promotion, and prior Codex task packs did not establish quality uplift.

### 2. Continue selective quality amplification

Keep v0.9.1 natural routing and verification-debt reminders enabled by default. This preserves the
candidate mechanism but risks repeating its token and time overhead without demonstrated benefit.

### 3. Remove the plugin runtime and ship only the benchmark harness

This has the lowest interference, but discards the loop fuse, privacy guard, and provenance value
that remain useful independently of quality scores.

## Product Contract

### Default mode

Default mode has these exact properties:

- no prompt-time route, baseline pack, residual check, repair prompt, or verification-debt context;
- no additional model call, retry, continuation, model substitution, effort change, or agent start;
- exact `gpt-5.6-sol` retains the deterministic v0.9 loop fuse;
- secret-shaped user input remains blocked before execution;
- unsupported, missing, and malformed model identifiers pass through;
- safety denials and turn stops explain only the policy that fired;
- raw prompt text, tool output, command text, file content, and credentials are never persisted.

The normal nonincident path emits no model-visible context. A safety denial is not counted as a
quality injection because it prevents a specific action and cannot ask the model to do more work.

### Experimental quality mode

The environment variable `SUPER_SOL_QUALITY_MODE=selective` restores the bounded v0.9.1 semantic
route and verification-debt behavior for explicit experiments. Any other value, including a missing
or malformed value, selects default safety-only mode. The mode is recorded as a small enum, not as
raw environment data.

Experimental quality mode is never enabled by installation, skill text, diagnostic mode, or the
benchmark harness. Results from that mode must be reported as a separate arm.

### Benchmark integrity mode

`SUPER_SOL_BENCHMARK_GUARD=1` enables test-mutation enforcement in controlled evaluations. Before
an edit-like tool runs, a normalized target under a configured test path is denied. Normal user
sessions leave this guard off because legitimate development often requires changing tests.

The guard accepts only repository-relative test roots supplied by the clean-room harness. Missing,
absolute, parent-traversing, or malformed roots fail closed in benchmark mode. The model receives a
short denial reason and no hidden-test path or content.

## Runtime Architecture

### Prompt surface

`super_sol_prompt_hook.py` performs secret detection, derives the exact model profile, resets an
existing Sol loop ledger, records the selected operating mode when state is required, and otherwise
returns no response. Existing route code remains available only behind experimental quality mode.

`prompt_dispatcher.py` keeps the low-startup path. In safety-only mode, actionable language and
semantic route keywords do not force the full routing import. Secret-shaped input and explicit
control variables still delegate to the strict processor.

### Tool and lifecycle surface

`super_sol_loop_hook.py` remains the sole default intervention engine. Soft WARN_ONCE transitions
are recorded but produce no additional context in safety-only mode. Existing block and stop
thresholds remain unchanged. Experimental quality mode may retain the old warning context for
ablation compatibility.

Benchmark test mutation is checked before loop-policy mutation so a denied test edit cannot consume
or distort replay counters.

### Local evidence ledger

A new bounded ledger stores only typed incident facts:

- schema version and operating mode;
- keyed session and turn identifiers already derived by the existing state layer;
- event kind, policy reason, decision, and monotonic timestamp;
- aggregate counters for pass, warn, deny, and stop outcomes.

The ledger does not store prompts, commands, tool responses, model output, paths, environment
values, or token values. It uses atomic replacement and a fixed maximum event count. Corrupt state
is quarantined and rebuilt without blocking stock Codex.

## Benchmark and Promotion

### Free Gate 0

The candidate must pass the complete non-live suite with at least 90% coverage, Ruff, formatting,
BasedPyright, package build, archive inventory, dependency audit, secret scan, loop replay, stock
hook lifecycle, and latency checks. Privacy tests must prove that sentinel prompt, command, path,
and output strings are absent from the plugin data tree.

### Safety replay gate

A deterministic replay suite covers:

- repeated tool request and repeated result thresholds;
- duplicate successful verifier denial;
- nested, concurrent, and total subagent budgets;
- automatic compaction stop;
- user-turn reset;
- benchmark test-edit denial and normal-session allowance;
- corrupt ledger recovery;
- safety-only silence on nonincident and warning-only transitions.

Every expected incident must produce one typed audit event. False denials in the benign replay set
must be zero.

### Prospective crossover

The paid comparison uses external held-out PR tasks and four arms per model profile:

1. raw, one attempt;
2. raw, same total budget with one preregistered retry policy;
3. v0.9.2 safety-only;
4. v0.9.2 experimental selective mode.

Safety-only promotion requires, within each supported model tier:

- mean paired quality delta at least 0;
- task-clustered 95% CI lower bound at least -2;
- full-pass and completion rates no lower than raw;
- paired token ratio at most 1.03;
- paired wall-time ratio at most 1.03;
- zero test mutation, contamination, hidden-test leakage, or provenance failure;
- zero benign-replay false denials;
- all induced loop incidents detected and bounded.

The raw same-budget retry arm tests whether the plugin beats spending the same budget on stock
Codex. Experimental selective mode cannot block the safety-only release and cannot support a default
quality claim without its own positive held-out confidence interval.

## Release and Compatibility

- Python package version: `0.9.2rc1`.
- Plugin version and Git prerelease: `0.9.2-rc1`.
- `v0.8.0` remains the stable quality evidence release until v0.9.2 passes its prospective gate.
- v0.9.0 and v0.9.1 artifacts, reports, and tags remain immutable.
- The release brief must distinguish observed safety evidence from untested quality hypotheses.
- No package publication, tag, GitHub release, or paid evaluation occurs before the corresponding
  local evidence and repository-owner authorization.

## Out of Scope

- raising the model capability ceiling;
- automatic model routing or provider calls;
- an operating-system security boundary;
- blocking ordinary user edits to tests;
- deriving token cost inside plugin hooks;
- retroactively reinterpreting v0.9 or v0.9.1 results.
